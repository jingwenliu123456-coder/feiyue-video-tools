# PM Skills Full Run — 飞跃视频工具

> 产品：飞跃视频工具（V22 主线）+ 飞跃命名工具 | 内部桌面批处理 | 投放/素材团队  
> 日期：2026-07-22 | 旁路：V23 裂变、V24 工作台

---

## product-vision

**选定愿景（一句话）**

> 让投放/素材同事**勾一套方案、批量出片、规范命名、一次交盘**——把重复劳动还给机器，把创意时间还给人。

**备选愿景（3 选 1 过程）**

| 选项 | 愿景句 | 取舍 |
|------|--------|------|
| A | 每一批素材，一次配置、零返工交盘 | 偏效率，缺情感 |
| B | 跨 Win/Mac，同一套方案，同一套命名，同一套品质 | 偏稳定，略技术向 |
| **C（选定）** | 勾方案 → 批量出片 → 规范命名 → 一次交盘 | 覆盖全流程 + 可感知结果 |
| D | 看得见再批处理，预览即信心 | 偏 V22 预览，缺命名闭环 |
| E | 从 V17 手工 FFmpeg 到一键批处理的内部标准工具 | 偏历史，非用户语言 |

**价值观**

| 价值观 | 产品体现 |
|--------|----------|
| 兼容优先 | `layer_enable`↔`logo_enable`、V20 模板在 V22 可加载 |
| 能力沉底、UI 可换壳 | `core/` + `modules/`，V24 换皮不重写引擎 |
| 同逻辑跨平台 | `platform_utils`、Mac Application Support 配置 |
| 处理与命名分离 | V20 外置命名工具，V24 Sheet 内嵌闭合链路 |

**与业务对齐**

- 直接服务素材产出 SLA（批处理耗时、返工率、命名纠错）
- 不对外商业化，成功标准是**团队人效**而非 ARR

## product-strategy

**Product Strategy Canvas（9 段）**

### 1. Vision

见 [product-vision](#product-vision) 选定句。

### 2. Market Segments

| 细分（按问题，非人口） | JTBD | 首要约束 | 优先序 |
|------------------------|------|----------|--------|
| **A. 日常批处理操作员** | 同一品牌模板反复出 9:16/1:1/落版组合 | 怕配错、怕返工、FFmpeg 环境坑 | **第一** |
| B. 多版本裂变投放 | 一批源素材 → 多语言/多尺寸/多落版 | 模板切换慢、目录混乱 | 第二（V23） |
| C. 规范命名/归档 | 输出后统一命名、接共享盘序号 | 手工命名易错、新旧规则混用 | 并列（命名工具） |

**为何先做 A**：V17–V22 全部迭代都围绕「单次批处理正确性 + 可预览」；用户量最大、痛点最频。

### 3. Relative Costs

| 维度 | 定位 |
|------|------|
| 策略 | **独特价值型**（非低价竞争） |
| 对比 | 免费通用工具（HandBrake/剪映）功能散；商用 MAM 成本高、上线慢 |
| 成本结构 | 内部维护 1–2 人 + FFmpeg 零授权；打包/跨平台是主要隐性成本 |

### 4. Value Proposition

| 细分 | What before | How | What after | Alternatives |
|------|-------------|-----|------------|--------------|
| A 操作员 | 手调 FFmpeg/PR 批处理，比例水印易错，改一处牵全身 | V22 网格布局 + 预览画布 + 方案模板 + 安全 FFmpeg 封装 | 预览确认后一键批处理，顺序随布局，模板秒加载 | 剪映批处理、PR 动作、手写脚本 |
| B 裂变 | 同一素材换模板跑 N 遍，人工改目录 | V23 分支引擎，每分支独立模板与输出目录 | 一次配置多分支连跑 | 多次开 V22 换模板 |
| C 命名 | 视频工具内嵌命名导致界面膨胀（V19 教训） | 外置 `naming_tool.py`，V24 Sheet 内嵌 | 跑完即命名，规则可复用 | Excel 批量改名、手工 |

### 5. Trade-offs（明确不做）

| 不做 | 原因 |
|------|------|
| 云端 SaaS / 协作审片 | 内部工具、素材敏感、无运维预算 |
| 非线性剪辑器 | 偏离批处理定位 |
| 预览 = 成片保证 | Tk 预览仅示意，真实以 FFmpeg 输出为准 |
| V23 与 V24 功能合并 | 裂变 vs 工作台场景不同，避免单 exe 臃肿 |
| 对外售卖 / 多租户 | 无商业化目标，减少支持负担 |
| 动态文字水印（V20 已砍） | 维护成本高、使用率低 |

### 6. Key Metrics

| 类型 | 指标 | 定义 |
|------|------|------|
| **North Star** | **规范交盘批次数 / 周** | 成功批处理且输出经命名规则确认的任务数 |
| **OMTM（本季）** | **批处理一次成功率** | 无需二次重跑的任务占比 |
| 输入 | 模板复用率、预览后修改率、跨平台启动成功率 | 驱动 NSM |
| 健康 | 批处理崩溃率、FFmpeg 探测失败率、Mac 配置写入失败数 | 护栏 |

### 7. Growth

| 项 | 内容 |
|----|------|
| 模式 | **组织内推广型**（非 PLG/SLG） |
| 渠道 | 素材组内训、Win/Mac 打包分发、模板库共享 |
| 扩展 | V24 工作台降低上手门槛 → 提高非核心用户采用 |
| 单位经济 | 无收入；ROI = 节省人时 − 维护成本 |

### 8. Capabilities

| 能力 | 自建 | 外采/依赖 |
|------|------|-----------|
| FFmpeg 批处理管线 | ✅ `core/ffmpeg_safe`, `overlay_processor` | FFmpeg 二进制 |
| 跨平台打包 | ✅ spec + Mac 脚本 | PyInstaller |
| UI | ✅ Tk 网格/工作台 | — |
| 命名规则引擎 | ✅ `naming_tool` | — |
| 云端存储/审片 | ❌ | — |
| 自动更新 | 弱 | 人工发版 |

### 9. Can't/Won't（防御性）

| 竞品/替代 | 为何难复制我们的组合 |
|-----------|----------------------|
| 通用剪辑软件 | 缺「方案模板 + 命名规范 + 内部落版资产」一体化 |
| 脚本/GitHub Actions | 缺可视化预览与非技术同事可操作 |
| 新内部工具 | 模板/配置兼容链（V17→V22）形成迁移成本；领域知识沉在 `overlay_processor` 时间轴逻辑 |

**策略一致性检查**：Vision（一次交盘）← Trade-off（命名外置又 Sheet 闭合）← NSM（规范交盘批次）← V24 工作台，逻辑闭环 ✅

**关键假设 & 轻量验证**

| 假设 | 验证实验 |
|------|----------|
| V24 比 V22 降低上手时间 | 5 名新用户完成任务计时 A/B |
| 预览足够减少返工 | 对比「用预览 / 不用预览」批次的二次重跑率 |

## value-proposition

### 细分 A：日常批处理操作员

| 6 段 | 内容 |
|------|------|
| **Who** | 投放/素材团队，负责品牌视频批量适配（9:16、水印、落版） |
| **Why (JTBD)** | 在 deadline 前把一批源片变成多规格投放素材 |
| **What Before** | PR/剪映/手写 FFmpeg 逐步处理；参数靠记忆；改比例要重来 |
| **How** | V22 加载方案模板 → 网格预览对齐水印/裁切 → 批处理顺序跟布局 → `ffmpeg_safe` 出片 |

| **Alternatives** | 剪映（缺内部落版链）、PR 批处理（学习成本高）、Python 脚本（无 UI） |

**价值主张陈述**：「对需要反复出同品牌多规格素材的操作员，飞跃视频工具用可预览的方案模板批处理，替代逐步手工调参，将返工从“猜位置”变成“看得见再出片”。」

### 细分 C：规范命名

| 6 段 | 内容 |
|------|------|

| **What Before** | 视频跑完后另开工具或 Excel 改名；易漏标签、序号冲突 |
| **How** | 命名工具规则引擎；V24 自动带入输出文件夹 |
| **What After** | 批处理→命名无断点；规则可保存复用 |
| **Alternatives** | Bulk Rename Utility、手工、视频工具内嵌（已证明会膨胀 UI） |

## porters-five-forces

> **适用说明**：非公开市场行业分析；以下将「行业」定义为**组织内素材批处理解决方案空间**。

| 力量 | 强度 | 分析 |
|------|------|------|
| **现有竞争** | 中 | 剪映/PR/脚本/GitHub Actions 并存；无单一垄断 |

| 力量 | 行动 |
|------|------|
| 替代品 | 强化模板+命名+内部落版，剪映无法复制 |
