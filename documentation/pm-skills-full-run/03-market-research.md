> **数据基础**：`01-product-vision-and-canvas.md`、`product-inventory.md`、`V17到V24演进思路.md`、代码与演进文档（无正式用户调研 CSV）

## user-personas

基于内部使用场景与 V17→V24 演进中的真实痛点归纳，共 3 个可行动 Persona。

### Persona 1：小雯 — 投放素材设计师（主力执行者）

| 维度 | 内容 |
|------|------|
| **人口/角色** | 25–32 岁，投放/素材设计师，日常处理 20–100 条短视频/周 |
| **核心 JTBD** | 把同一批源素材快速变成多语言、多尺寸、带品牌落版与水印的成片，按时交盘 |
| **Top 3 痛点** | ① Premiere 手搓工序重复、易漏步骤 ② 批完才发现水印/落版位置错 ③ 共享盘文件名乱、覆盖风险 |
| **Top 3 期望收益** | ① 模板一键加载 ② 预览后再批 ③ 命名规范自动化 |
| **意外洞察** | 她更在意「布局可调」而非「更多滤镜」——模块顺序即工序顺序（V22 网格） |
| **产品契合** | V22 模板 + 预览画布 + 命名工具闭环；摩擦：Mac 首次配置、旧模板兼容报错 |

### Persona 2：老周 — 设计负责人 / 规范管理员

| 维度 | 内容 |
|------|------|
| **人口/角色** | 30–40 岁，带 3–8 人素材小组，负责品牌规范与交付质量 |
| **核心 JTBD** | 让全组用同一套成片标准（落版、水印、命名），减少返工与对表 |
| **Top 3 痛点** | ① 每人参数不一致 ② 新人上手慢 ③ 跨 Win/Mac 环境工具跑不起来 |
| **Top 3 期望收益** | ① 可分发方案模板库 ② 命名字段/标签库统一 ③ 打包即用、内置 FFmpeg |
| **意外洞察** | 他愿意接受「多开一个命名工具 exe」换「视频工具发版稳定」——V20 外置命名是正确取舍 |
| **产品契合** | 方案模板 JSON + 命名规则引擎；缺口：无集中模板仓库、无权限/审计 |

### Persona 3：阿 Ken — 跨平台协作者（Mac 用户）

| 维度 | 内容 |
|------|------|
| **人口/角色** | 28–35 岁，Mac 主力机，与 Win 同事共用 NAS/网盘 |
| **核心 JTBD** | 在 Mac 上跑与 Win 同事相同的批处理与命名规则，输出可直接进共享盘 |
| **Top 3 痛点** | ① Win 打包 zip 在 Mac 不能直接用 ② 配置写进 .app 只读崩溃 ③ FFmpeg/字体路径差异 |
| **Top 3 期望收益** | ① 本机 build 的 .app ② Application Support 统一配置路径 ③ 与 Win 模板互通 |
| **意外洞察** | Mac 用户更频繁触发「环境类」工单，而非「功能缺失」——平台层是 adoption 瓶颈 |
| **产品契合** | `platform_utils` + Mac 打包脚本；摩擦：需同事本机构建、文档偶有 HIGO/V20 滞后 |

## user-segmentation

按行为、JTBD、需求划分至少 3 段；规模为团队内估算。

### Segment A：日常批处理执行段（~60%）

| 项 | 内容 |
|----|------|
| **规模** | 约 60% 活跃用户 |
| **行为特征** | 高频单次批处理；深度使用模板；偶尔调布局；Win 为主 |
| **JTBD** | 文件夹进 → 模板加载 → 批量出片 |
| **痛点** | 返工、预览不准、日志难定位失败文件 |
| **产品契合** | 高；最依赖 V22 主线 |
| **差异化价值** | 强化预览准确度提示、失败文件一键重跑 |
| **优先级** | **Invest** — 产能核心 |

### Segment B：规范治理段（~25%）

| 项 | 内容 |
|----|------|
| **规模** | 约 25%（含管理者兼用） |
| **行为特征** | 维护模板库与命名标签；培训新人；检查输出命名 |
| **JTBD** | 标准可复制、可传承 |
| **痛点** | 模板版本漂移、命名规则升级、无统一分发 |
| **产品契合** | 中高；命名工具 + 模板 JSON |
| **差异化价值** | 模板版本号、标签库升级向导、一页 onboarding |
| **优先级** | **Invest** — 降低组织摩擦 |

### Segment C：多方案裂变段（~10%）

| 项 | 内容 |
|----|------|
| **规模** | 约 10%（大促/多语言战役期上升） |
| **行为特征** | 同一批素材连跑多模板；用 V23 或手换模板 |
| **JTBD** | 一次输入、多分支输出 |
| **痛点** | UI 状态与模板快照混淆、分支目录管理 |
| **产品契合** | 中；V23 实验线 |
| **差异化价值** | 裂变配置可视化、分支 diff 预览 |
| **优先级** | **Maintain** — 战役期再加强 |

### Segment D：工作台尝鲜段（~5%）

| 项 | 内容 |
|----|------|
| **规模** | 约 5% |
| **行为特征** | 试用 V24；重视命名 Sheet 内嵌、链路可视化 |
| **JTBD** | 单窗口闭环、低认知负担 |
| **痛点** | V24 未进打包主线、与 V22 双轨 |
| **产品契合** | 中（UX 高、稳定性待验证） |
| **优先级** | **Maintain / 观察** |

## market-segments

从「可服务市场」视角识别 5 段；含内部主战场与假设性外延。

| 段名 | 规模估 | 增长 | 核心 JTBD | 主要痛点 | 飞跃产品契合 |
|------|--------|------|-----------|----------|--------------|
| **内部投放素材组** | 15–30 人（当前） | 稳定 | 批量出片+规范命名 | 重复劳动、跨机 | **极高** — 主战场 |
| **同公司其他素材/运营组** | +20–50 人（潜在） | 中 | 同上 | 不知工具有、无模板 | **高** — 需内部推广 |
| **小型广告工作室** | 外部 TAM 大 | 中 | 多尺寸投放素材 | 人力贵、缺批处理 | **中** — 需产品化/支持 |
| **MCN / 短视频矩阵** | 外部 | 高 | 量产同质化短片 | 剪辑软件过重 | **低中** — 工序不匹配 |
| **企业品牌内训视频组** | 外部 | 低 | 长片剪辑+包装 | 要 NLE 深度 | **低** — 非目标 |

### 各段详表（重点 3 段）

#### 1. 内部投放素材组（Primary）

- **人口特征**：设计师、素材专员；中英多语言素材；9:16 / 1:1 等比例
- **Desired Gains**：周产出量↑、返工率↓、文件名可检索
- **障碍**：Mac 打包、模板迁移
- **竞品替代**：Premiere 手动、剪映批量（弱命名）

#### 2. 同公司扩展组（Secondary）

- **决策链**：设计负责人推荐 → IT/行政分发 exe
- **障碍**：无对外文档、无培训材料
- **机会**：内部案例 + 模板包

#### 3. 小型广告工作室（Hypothesis — 未验证）

- **付费意愿**：若有 SLA 可能按席位；**当前 N/A 验证**
- **产品缺口**：自动更新、License、工单系统

## market-sizing

**市场定义**：桌面端「投放短视频批处理 + 规范命名」场景。地理：当前以内部团队为主；外部为假设延伸。

### TAM / SAM / SOM

| 方法 | TAM | SAM | SOM（1–3 年） |
|------|-----|-----|----------------|
| **Top-down** | 全球视频营销软件 ~$80–100B 大盘中，SMB 批处理/自动化子集难单独切分；粗估相关工具层 **$2–5B** | 国内投放素材工具链中「非 NLE 批处理」 niche：**$50–200M**（极宽假设） | 内部工具 **$0 收入**；若产品化 50–200 席位 × ¥500–2000/年 ≈ **¥2.5–40 万/年** |
| **Bottom-up** | 内部 15–30 人 × 0 元 = **$0** | 可服务：内部全员 + 50 扩展用户 | 12 个月内：**100% 内部渗透**（30 人）为现实目标；外部 **<5%** 渗透率 |

### 汇总表

| 指标 | 当前估计 | 2–3 年预测 |
|------|----------|------------|
| **TAM** | 外部 hypothetic $2–5B 层 | 随短视频投放预算增，批处理需求增 |
| **SAM** | 内部 30 人 + 潜在同公司 50 人 | 80–100 内部用户（组织扩张） |
| **SOM** | 30 活跃用户（目标） | 内部 90%+ 渗透；外部售卖 **N/A 除非战略变更** |

### 增长驱动

- 多语言、多尺寸投放需求增加 → 裂变场景变多  
- Mac 同事占比上升 → 跨平台质量决定 SAM  
- V24 工作台若进主线 → 降低命名切换摩擦 → 使用率上升  

### 关键假设与风险

| # | 假设 | 置信度 | 验证方式 |
|---|------|--------|----------|
| 1 | 内部全员可被 V22 覆盖 | 中 | 活跃使用统计（年报雏形） |
| 2 | 外部工作室愿为「工序模板」付费 | 低 | **N/A** — 无售卖计划 |
| 3 | 剪映/PR 不会覆盖批处理+命名闭环 | 中 | 竞品功能跟踪 |
| 4 | Mac 打包成本可接受 | 中 | Mac 同事成功 build 率 |

**说明**： revenue 型 TAM 对内部工具 **不适用**；以上以外部 hypothetic 仅供战略讨论。

## competitor-analysis

**市场定义**：投放短视频「批量工序处理 + 输出规范」——非通用 NLE 市场。

### 市场概览

| 项 | 内容 |
|----|------|
| 规模趋势 | 短视频投放量持续增长；批处理需求从脚本走向低代码/桌面工具 |
| 关键成功因素 | 工序可复用、批量稳定、命名规范、预览可信、跨平台 |
| 竞争强度 | 通用剪辑软件强；垂直批处理工具分散；**内部定制工具**为真实替代 |

### 竞争集合（5 个直接/ adjacent 对手）

| 竞争者 | 定位 | 与飞跃关系 |
|--------|------|------------|
| Adobe Premiere Pro | 专业 NLE | 功能重叠（手动批处理）；缺命名闭环 |
| 剪映专业版 | 消费级/轻专业剪辑 | 批量弱；模板生态强 |
| FFmpeg + 自写脚本 | 工程师方案 | 灵活但无 UI、无命名 |
| Shutter Encoder / HandBrake | 转码批处理 | 无落版/水印工序链 |
| 云端素材 DAM + 工作流（如部分 MAM） | 企业资产流 | 过重、无桌面轻量批处理 |

### 各竞品简档

#### 1. Adobe Premiere Pro

| 维度 | 评估 |
|------|------|
| 优势 | 时间线精度、生态、团队熟悉 |
| 劣势 | 批量工序慢、命名靠人工、难固化「裁切→9:16→MOV 水印→浮层落版」链 |
| 定价 | 订阅 ¥数百/月/席位 |
| 威胁 | 低（不同 JTBD）；用户已用 PR 做精剪 |
| 飞跃差异化 | **方案模板 + 一键文件夹批处理 + 命名工具** |

#### 2. 剪映专业版

| 维度 | 评估 |
|------|------|
| 优势 | 上手快、模板多、适合单条快剪 |
| 劣势 | 批量路径长；企业命名规范难嵌入；Win/Mac 行为不完全一致 |
| 威胁 | 中（新人愿用剪映） |
| 飞跃差异化 | **工序管线可开关、旧版文件名清理、共享盘序号策略** |

#### 3. FFmpeg + 脚本

| 维度 | 评估 |
|------|------|
| 优势 | 完全可控、滤镜任意 |
| 劣势 | 无预览 UI、维护成本高、音画时间轴坑（V21 已踩） |
| 威胁 | 低（团队已转向飞跃） |
| 飞跃差异化 | `ffmpeg_safe` + `overlay_processor` 沉淀 |

#### 4. Shutter Encoder

| 维度 | 评估 |
|------|------|
| 优势 | 免费、转码批处理成熟 |
| 劣势 | 无落版逻辑、无命名、无模板 |
| 威胁 | 低 |
| 飞跃差异化 | 完整投放工序链 |

#### 5. 内部「手工 + Excel 对表」

| 维度 | 评估 |
|------|------|
| 优势 | 零部署 |
| 劣势 | 错误率高、不可扩展 — **当前最大竞品** |
| 威胁 | 高（习惯惯性） |
| 飞跃差异化 | 模板复用、日志、撤销批处理 |

### 差异化机会汇总

- 未满足：**预览≈成片**（仍部分示意）、**模板中心分发**、**Mac/Win 模板同步**  
- 应强调：**投放工序专用**而非「又一个剪辑器」  
- 12–18 月风险：剪映加强批量；若对外售卖需补 License/更新机制

## customer-journey-map

**旅程 Persona**：小雯（投放素材设计师）· **工具**：飞跃视频工具 V22 + 命名工具

### 关键时刻

| 时刻 | 定义 |
|------|------|
| **Aha** | 首次加载团队模板，10 分钟内批量出 5 条合格成片 |
| **Moment of Truth** | 第一次预览画布对齐水印后批处理 — 信任建立/崩塌 |
| **Churn 触发** | Mac 跑不起来；模板加载崩溃；批处理覆盖错文件 |

### 旅程表

| 阶段 | 触点 | 用户行为 | 情绪 | 痛点 | 机会 |
|------|------|----------|------|------|------|
| **认知** | 同事推荐、U 盘/网盘 | 听说「飞跃」能批量落版 | 😐 好奇 | 不知 Win/Mac 用哪个包 | 一页 Quick Start + 双端下载链 |
| **考虑** | 对比 PR 手搓 | 评估是否值得换工作流 | 🤔 谨慎 | 怕学习成本 | 30 分钟 onboarding 清单 |
| **获取** | 解压 exe / Mac build | 复制 ffmpeg、双击启动 | 😊→😟 | Mac 需本机构建 | 预构建 .app + 配置向导 |
| **上手** | 选文件夹、加载模板 | 勾选模块、看预览 | 😊 | 模块多、不知顺序 | 默认布局 + 模板说明注释 |
| ** engagement** | 日常批处理 | 每周重复模板→出片 | 😊 | 失败文件定位慢 | 失败列表 + 打开所在文件夹 |
| **留存** | 模板更新、版本升级 | 跟随 V22 打包更新 | 😐 | 旧模板兼容报错 | 模板版本迁移工具 |
| **命名闭环** | 打开命名工具 | 输出目录扫描改名 | 😊 | 需另开 exe（V22） | V24 Sheet 内嵌（实验） |
| ** advocacy** | 教新人、分享模板 | 复制 JSON 模板给同事 | 😄 | 无统一模板库 | 内部模板 Git/共享文件夹规范 |

### 优先改进（Impact × Effort）

| 优先级 | 改进项 | 类型 |
|--------|--------|------|
| P0 | Mac 一键包 + Application Support 说明 | Quick win |
| P0 | 新同事 30 分钟 onboarding 文档 | Quick win |
| P1 | 批处理失败聚合与重试 | 中期 |
| P1 | 模板库集中存放 + 版本字段 | 中期 |
| P2 | V24 稳定后进打包主线 | 战略 |

## sentiment-analysis

**数据说明**：无结构化 NPS/问卷 CSV；以下基于演进文档中的用户反馈线索、V24 设计动机、Mac 打包工单类型做 **定性 sentiment 合成**。正式调研前置信度：**中低**。

### Segment 1：日常执行设计师

| 项 | 内容 |
|----|------|
| **Sentiment** | **+0.55**（偏正） |
| **满意度驱动** | 模板省事、批量快、预览降低返工 |
| **不满驱动** | 预览与成片偶有偏差、日志冗长 |
| **代表反馈主题** | 「勾模板就能跑」✅ · 「批完才发现位置偏一点」⚠️ |
| **建议** | 预览区标注「示意帧」；关键模块批前强制预览 |

### Segment 2：规范管理者

| 项 | 内容 |
|----|------|
| **Sentiment** | **+0.40** |
| **满意度驱动** | 命名规则可配置、模板可分发 |
| **不满驱动** | 模板字段随版本变、文档滞后（HIGO/V20 文案） |
| **建议** | 模板 schema 版本号；更新 PACKAGING 到 V22 |

### Segment 3：Mac 用户

| 项 | 内容 |
|----|------|
| **Sentiment** | **+0.10**（勉强可用） |
| **满意度驱动** | 跨平台逻辑统一后体验接近 Win |
| **不满驱动** | .app 只读配置、需本机 build、Win zip 不能用 |
| **建议** | Mac 预打包；首次启动配置检测 |

### Segment 4：V24 尝鲜用户

| 项 | 内容 |
|----|------|
| **Sentiment** | **+0.65**（UX）/ **+0.30**（稳定） |
| **满意度驱动** | 呼吸感 UI、命名 Sheet、链路可视化 |
| **不满驱动** | 双轨版本、未进 exe 主线 |
| **反馈来源** | V24 设计文档：「表格感重、命名要另开 exe」 |
| **建议** | 稳定后合并主线；保留 V22 作为 fallback |

### 跨段 universal 主题

| 主题 | 极性 | 频率 | 行动 |
|------|------|------|------|
| 重复劳动减少 | + | 高 | 继续 invest 模板/裂变 |
| 跨机环境 | − | 中 | Mac 打包 P0 |
| 命名闭环 | +/− | 高 | V24 或快捷打开输出目录 |
| 对外售卖 | **N/A** | — | 无需求信号 |

### NPS 代理

- **N/A（正式 NPS）**：未跑问卷；若内部 5 分制估算：**Promoter ~55% · Passive ~30% · Detractor ~15% → eNPS ≈ +40**（Mac 段拉低）
