## ideal-customer-profile

### Firmographic / 组织画像

| 字段 | Ideal 描述 |
|------|------------|
| 组织 | 投放驱动的素材/创意团队（当前：内部投放素材组） |
| 规模 | 5–30 人同时使用；周产出 100+ 条短视频变体 |
| 地理 | 中国大陆为主；Win + Mac 混合桌面 |
| 行业 | 效果广告 / 品牌投放素材生产 |
| 决策链 | 设计负责人定规范 → 执行设计师日用 → 行政/IT 协助分发 exe |

### Behavioral 行为画像

| 行为 | 描述 |
|------|------|
| 发现方式 | 同事口口相传、组长分享模板包 |
| 评估标准 | 30 分钟内能否出第一条片；是否覆盖落版+水印+9:16 |
| 技术素养 | 会用 PR/剪映；不一定懂 FFmpeg |
| 切换频率 | 低（模板沉淀后粘性高） |
| 协作 | 共享 NAS/网盘；文件名需可检索 |

### JTBD 映射

| 类型 | Job |
|------|-----|
| **Functional** | 批量完成裁切→比例→水印→落版→叠加，并规范命名 |
| **Emotional** | 少加班、少怕覆盖错文件、批前有把握 |
| **Social** | 输出「像团队标准」而非个人风格 |
| **Avoid** | 重复手搓时间线、Excel 对表改名 |

### Top Pain Points（5–7）

| # | 痛点 | 影响 |
|---|------|------|
| 1 | 同一工序每天重复 | 产能瓶颈 |
| 2 | 参数人传人失真 | 返工、品牌不一致 |
| 3 | Mac/Win 环境不一致 | 采用失败 |
| 4 | 批完才发现视觉错误 | 信任损失 |
| 5 | 共享盘命名混乱 | 协作摩擦 |
| 6 | 多方案战役换模板慢 | 大促产能 |
| 7 | 新人上手无文档 | 支持成本 |

### 量化影响（内部估）

| 指标 | Before | After（工具成熟） |
|------|--------|-------------------|
| 单条工序时间 | 15–30 min（PR 手搓） | 2–5 min（批处理摊销） |
| 返工率 | ~15–20%（估） | 目标 <5% |
| 新人上手 | 1–2 天 | 目标 0.5 天 |

### 不合格 ICP（Disqualification）

| 非 ICP | 原因 |
|--------|------|
| 长片叙事剪辑团队 | 需要 NLE 深度 |
| 纯静态设计组 | 无视频批处理需求 |
| 无 Windows/Mac 桌面环境 | 产品形态不匹配 |
| 期望云端协作 DAM | 当前无此能力 |

### Ideal-of-the-Ideal（最高价值子集）

> **多语言战役期的 Win 投放设计师**：高频用模板、周批处理 >50 条、愿分享模板 — 驱动模板库与裂变需求。

## growth-loops

内部工具的增长 = **采用扩散 + 使用加深**，非 viral 获客。

### 五类 Loop 评估

| Loop 类型 | 契合度 | 说明 |
|-----------|--------|------|
| **Viral** | 2/10 | 输出视频不携带产品品牌；**N/A 外部分享获客** |
| **Usage** | 8/10 | 每次批处理加深模板依赖；用得越多切换成本越高 |
| **Collaboration** | 7/10 | 模板 JSON 在同事间复制 = 隐性协作 loop |
| **User-Generated** | 6/10 | 用户产出的「方案模板」供他人加载 |
| **Referral** | 5/10 | 内部推荐无金钱激励；靠节省工时口碑 |

### 主 Loop：Usage + Template UGC

```
用户批处理成功 → 保存为方案模板 → 分享给同事 → 同事加载模板 → 批处理成功 ↑
```

| 参数 | 估 |
|------|-----|
| 每活跃用户模板分享次数/季 | 1–3 |
| 模板→新用户激活转化 | ~60%（内部） |
| Loop 周期 | 1–2 周（战役节奏） |

### 次 Loop：Collaboration（规范管理者）

```
负责人定命名规则/标签库 → 全组命名工具统一配置 → 共享盘可检索 → 减少协作摩擦 → 工具粘性 ↑
```

### 30–60–90 天 Loop 建设

| 天数 | 动作 |
|------|------|
| 30 | 模板导出/导入 UX 优化；模板命名规范 |
| 60 | 共享目录「团队模板库」；年报展示「本月最热模板」 |
| 90 | V23 裂变模板 pack；Mac/Win 模板 sync 说明 |

**Referral 激励（红包/积分）**：**N/A** — 内部无需；节省工时即激励。

## competitive-battlecard

**对战对象**：Adobe Premiere Pro（内部最常出现的「为什么不继续用手搓」）

### Company Overview — Premiere Pro

| 项 | 内容 |
|----|------|
| 厂商 | Adobe |
| 定位 | 专业非线性剪辑与时间线精修 |
| ICP | 影视、广告、全类型视频制作 |
| 一句话 | 「行业标准的创意剪辑与时间线工具」 |

### Quick Comparison

| 能力 | 飞跃视频工具 | Premiere Pro | Winner |
|------|--------------|--------------|--------|
| 投放工序批处理（裁切→比例→水印→落版链） | 一键文件夹批处理 + 模块开关 | 需动作/预设；批量弱 | **飞跃** |
| 方案模板复用 | JSON 整套参数 | 项目/预设；字段不完全对齐 | **飞跃** |
| 规范命名闭环 | 独立命名工具 + 字段/标签库 | 无；靠人工 | **飞跃** |
| 预览再批 | V22 画布示意 | 时间线实时预览 | Tie（PR 更准，飞跃更快） |
| 创意剪辑/调色/复杂时间线 | 不支持 | 完整 | **PR** |
| 跨平台内部打包 | 内置 FFmpeg exe/app | 订阅安装 | **飞跃**（内部分发） |
| 定价 | 内部 $0 | 订阅制 | 语境不同 |
| 学习曲线（投放批处理场景） | 低（勾选项） | 中高 | **飞跃** |

### Where We Win

- **工序固化**：浮层落版音画、MOV 水印、9:16 模糊底 — 团队踩坑已写入代码  
- **命名闭环**：旧版文件名清理、序号策略 — PR 无  
- **批量产能**：文件夹级处理；同名策略防覆盖  

### Where They Win

- **像素级精修**：需改某一帧时仍要 PR → 定位：**互补非替代**  
- **行业通用性**：新人已会 PR → 对策：飞跃负责「出片」，PR 负责「精修例外」  

### Common Objections & Responses

| 同事说 | 回应 |
|--------|------|
| 「我会 PR，不需要新工具」 | 「PR 适合精剪；飞跃把你们每天重复的 6 步合成一次批处理，省的是重复劳动不是替代创意」 |
| 「预览不准怎么办？」 | 「预览是示意对齐；关键模块建议短片段试跑；比批完 50 条才发现错省得多」 |
| 「多装一个 exe 麻烦」 | 「模板配一次；以后每周省几小时；命名工具避免共享盘覆盖事故」 |
| 「Mac 上能用吗？」 | 「可以；用团队 Mac 包 + Application Support 配置；有问题找 Mac 指南」 |

### Landmines to Plant（引导提问）

- 「你们一批素材通常要出几种尺寸/语言？」→ 突出批量  
- 「共享盘里找文件主要靠文件名吗？」→ 突出命名工具  
- 「落版音和主片 BGM 重叠时怎么混？」→ 突出 overlay_processor 已处理  

### Win/Loss Patterns

| 模式 | 说明 |
|------|------|
| **Win when** | 多尺寸短视频批量、模板已备好、战役期产能压力 |
| **Lose when** | 单条精修、复杂叙事剪辑、用户不愿切换习惯 |
| **关键差异化** | 投放工序模板 + 命名 — 不是「更好的剪辑器」 |

### 第二 Battlecard 摘要：剪映专业版

| 对比点 | 飞跃赢 | 剪映赢 |
|--------|--------|--------|
| 企业命名规范 | ✅ | ❌ |
| 可编排 FFmpeg 工序链 | ✅ | 弱 |
| 模板生态/上手 | 弱 | ✅ |
| 单条快速剪辑 | 弱 | ✅ |

**完整第三 battlecard（FFmpeg 脚本）**：**N/A 单独成卡** — 内部已基本迁移至飞跃；对策见上「脚本无 UI 无命名」。
